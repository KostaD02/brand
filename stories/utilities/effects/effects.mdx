# Effects

Shadow, the pop and lift treatments, the accent rail, opacity, transition and interaction
utilities, plus the animation set: `kd-animate-*`, `kd-stagger`, `kd-typewriter`, the
scroll-driven `kd-reveal` and the once-per-session `kd-intro`.

## Shadow

`kd-shadow-{sm|md|lg|side|none}`. The shadow tokens are theme keys, so they soften in the
light theme rather than keeping the dark values.

<Canvas of={EffectsStories.Shadow} />

## Pop

`kd-pop` and `kd-pop-lg` apply the signature treatment: on hover and focus the element
lifts by a translate and casts a hard offset shadow with no blur.

<Canvas of={EffectsStories.Pop} />

> The colour comes from `--kd-shadow-pop-color`, which resolves where it is used, so
> setting it on the element retints the shadow. The flat `--kd-shadow-pop` token does not
> consult it, so components reading that token directly cannot be retinted the same way.

## Lift

`kd-lift` is the straight vertical counterpart: 7px up on hover and focus, with the large
soft shadow instead of the hard offset one. Reach for it on a grid of cards where the
diagonal drift of `kd-pop` would read as wobble. One or the other, never both on the same
element.

<Canvas of={EffectsStories.Lift} />

## Opacity

`kd-opacity-{0|25|50|75|100}`.

<Canvas of={EffectsStories.Opacity} />

> The ladder is hardcoded rather than read from the opacity tokens, so
> `--kd-opacity-muted` (0.65) has no matching class.

## Transition

`kd-transition` applies the base transition. `kd-transition-fast`, `kd-transition-slow`
and `kd-transition-none` take the other durations.

## Interaction

`kd-cursor-{pointer|default|not-allowed|wait|text|grab}`,
`kd-pointer-{none|auto}` and `kd-select-{none|text|all}`.

> `kd-pointer-none` also stops hover and focus styles firing, so pairing it with
> `kd-cursor-not-allowed` means the cursor never shows, because the element cannot be hovered at
> all. Use one or the other.

## Focus ring

`kd-focus-ring` applies the dashed accent outline on `:focus-visible`. The reset already
does this globally; the class is for elements that have opted out and need it back.

<Canvas of={EffectsStories.FocusRing} />

## Rail

`kd-rail` draws the 13px accent bar down the leading edge. It is the same mixin `pre` and
`kd-teaser` already carry, lifted out so anything else can wear the mark.

<Canvas of={EffectsStories.Rail} />

> The bar is a `::before` sitting on top of the box, not a border, so it does not take up
> any space. Pad the leading edge past 13px yourself or the first character sits under it.

## Animations

`kd-animate-{fade-in|fade-out|fade-up|drop-in|slide-in-start|slide-in-end|glow}` each set
an animation name on top of a shared base. The base declares none of its inputs; it reads
`--kd-animate-duration`, `--kd-animate-delay`, `--kd-animate-easing` and
`--kd-animate-fill` with fallbacks to `--kd-duration-base`, `0s`, `--kd-easing` and
`both`. The element needs nothing else, no `animation` declaration of its own.

<Canvas of={EffectsStories.Animate} />

> The demo slows them to 1.2s to make them readable; the default is `--kd-duration-base`,
> a quarter of a second. They run once on mount, so reload the page to watch them again,
> and `kd-animate-fade-out` correctly leaves its cell at zero opacity when it lands.

> The slides travel the full width of the element and `kd-animate-fade-up` the full
> height, so on a short pill they are a nudge and on a whole section they are a sweep.

## Inherited timing

Because the base only reads its inputs, `--kd-animate-duration` and `--kd-animate-delay` can
be set on an ancestor and inherit down to every animated descendant. One declaration on a
section wrapper gives the whole section a single duration, with nothing on the children but
their animate class.

<Canvas of={EffectsStories.InheritedTiming} />

> This is a change in behaviour. The base used to re-declare both variables on the element
> itself, which meant an ancestor hook was inert. `kd-stagger` leans on the same shape: it
> writes `--kd-animate-delay` on each child for the base to read, and a duration set once on
> the `kd-stagger` parent reaches all of them.

## Fill mode

`--kd-animate-fill` defaults to `both`, so a one shot animation latches its final keyframe
and holds it forever. That is right for an entrance: `kd-animate-fade-up` stays where it
landed. It is wrong for an attention cycle. `kd-animate-glow` ends on `--kd-text-muted`, so
under the default fill the text is left muted rather than going back to its own colour.
Setting `--kd-animate-fill: none` releases it the moment the animation finishes.

<Canvas of={EffectsStories.FillMode} />

## Stagger

`kd-stagger` sets `--kd-stagger-step` to 200ms on the parent and hands each of its first
eight children a delay one step larger than the last. Put an animate class on the children
and the list arrives in sequence with no per-item CSS and no loop in the consumer.

<Canvas of={EffectsStories.Stagger} />

> A ninth child gets no rule, so it keeps the 0s default and lands with the first one.
> Keep staggered lists inside eight items, or accept that the tail arrives together.

## Reveal

`kd-reveal` holds back the `kd-animate-*` animations on an element, and on everything
inside it, until the element scrolls into view. It is a trigger, not an animation of its
own: pair it with any animate class, set the timing the usual way, and the first time the
element enters the viewport it gets `kd-reveal--in` and the held animations run.

<Canvas of={EffectsStories.Reveal} />

It needs two things from the page. A `kd-js` class on `<html>`, set by an inline script in
`<head>` so it is there before first paint, and one call to `reveal()` once the DOM is
parsed:

```html
<script>
  if ("IntersectionObserver" in window) {
    document.documentElement.classList.add("kd-js");
  }
</script>
```

```js
import { reveal } from "@kostad/brand/js";

reveal();
```

> Without `kd-js` nothing is held back and the animations simply run on load, so a page
> whose JavaScript never arrives shows all of its content. That is the point of the flag:
> the stylesheet never hides anything on its own. It also means the flag has to be set
> synchronously in `<head>`. Set it later and the animations start, then freeze mid-way.

> A held element waits on its first keyframe, which for `kd-animate-fade-up` is invisible
> and a full height lower than its final spot. It gets `pointer-events: none` for as long
> as it waits, so it cannot catch clicks meant for the content it overlaps.

> Under `prefers-reduced-motion: reduce` nothing is held back at all. Content never waits
> for the observer, and the reset collapses the animations as usual.

### Stagger

`kd-stagger` works unchanged: put `kd-reveal` on the parent and the animate class on the
children, and the sequence starts when the parent enters the viewport.

<Canvas of={EffectsStories.RevealStagger} />

### Options

`reveal(root, options)`. `root` is where to look for `kd-reveal` elements, `document` by
default; call it again with a subtree for elements added later. `options` goes straight to
the `IntersectionObserver`, plus a `prefix` for a build compiled with a different
`$prefix`. The defaults are `threshold` `0` and `rootMargin` `"0px 0px -10% 0px"`, so an
element counts as in view once its top edge is a tenth of the viewport in. Each element
fires once, and the observer is returned for anything that needs to disconnect it.

> The trigger is the top edge rather than a visible ratio on purpose. A section several
> screens tall never reaches a ratio threshold on a phone and would stay hidden.

## Intro

`kd-intro` marks an entrance that should play once per browser session: the navbar
dropping in, a hero staggering up. When `<html>` carries `kd-no-intro`, every child of a
`kd-intro` element has its animation removed, and nothing else changes.

<Canvas of={EffectsStories.Intro} />

The flag comes from the same inline script, keyed on `sessionStorage`:

```html
<script>
  try {
    if (sessionStorage.getItem("kd-intro")) {
      document.documentElement.classList.add("kd-no-intro");
    }
    sessionStorage.setItem("kd-intro", "1");
  } catch (error) {}
</script>
```

> `sessionStorage` throws rather than returning `null` in some private modes and sandboxed
> frames, hence the `try`. When it throws the intro simply plays every time.

> The rule targets the children, not the `kd-intro` element itself, so a container with an
> entrance of its own, `kd-drawer__panel` for instance, keeps it while its items skip
> theirs.

## Typewriter

`kd-typewriter` types a line out and blinks a caret after it, driven by
`--kd-typewriter-steps` and `--kd-typewriter-duration`.

<Canvas of={EffectsStories.Typewriter} />

> The step count has to equal the number of characters in the text. Get it wrong and the
> animation stops short of the last glyph or overshoots it. Fourteen steps for
> "Page not found".

> It animates width against `white-space: nowrap`, so it is one line only, and the width
> runs to 100% of the containing block rather than to the text. Give it a parent no wider
> than the line, `kd-w-fit` for instance, or the caret finishes far past the last letter.

## Reduced motion

None of these need a guard of their own. The reset already collapses animation and
transition durations to nothing under `prefers-reduced-motion: reduce`, and that rule
covers every class on this page. `kd-reveal` goes one step further and stops holding
anything back, so nothing on the page waits for a scroll.

## Customising

The `kd-animate-*` base reads four hooks and declares none of them:
`--kd-animate-duration`, `--kd-animate-delay`, `--kd-animate-easing` and
`--kd-animate-fill`. Set any of them inline for a one-off, or on an ancestor to cover a
whole subtree. `--kd-stagger-step` sits on the `kd-stagger` parent and retimes the whole
sequence at once, and `--kd-typewriter-steps` and `--kd-typewriter-duration` are declared on
`kd-typewriter` itself. `kd-reveal` adds no hooks of its own; its timing is whatever the
held animation reads, and its trigger is tuned through the `reveal()` options.
