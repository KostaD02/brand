# Syntax

The colour theme for highlighted code. It highlights nothing itself: run highlight.js, or
anything else that emits the same `hljs-*` class names, and this layer paints the result.
Every colour in the `hljs-*` rules resolves to a `--kd-code-<role>` custom property, so a
project recolours the whole theme by reassigning properties and never by rewriting
selectors. The roles are modelled on VS Code's Dark+ theme: functions share one colour;
types another; variables, parameters and properties a third. highlight.js has one
`built_in` class for built-in functions and objects alike, and that class takes the type
colour. [Tokens](?path=/docs/tokens--docs) lists each role's dark and light value.

Two roles are there for editor themes only. highlight.js has a single class for all
keywords and none for invalid code, so no rule here reads `--kd-code-control` or
`--kd-code-invalid`, and picking either in the playground changes nothing.

## Example

`.hljs` sets the same code background and foreground that `pre` already carries, so the
highlighter's wrapper lands on styling that is right before a single token is coloured.
Every keyword takes the storage colour, `return` as much as `import` and `const`, and so
do `false`, `true` and `document`.

## Stylesheets

Selectors, property names and values land on different roles, which is why a stylesheet
does not read as one colour. `.hljs-selector-class` takes the escape colour, which
selectors share with escape sequences; property names take the variable colour. A value
takes the colour of what it is: `1rem` is a number, and `var` counts as a built-in and
takes the type colour, while its parentheses and the custom property inside stay in the
plain code colour. The only string is the `@use` path.

<Canvas of={SyntaxStories.Stylesheet} />

## Markup

A tag is an `hljs-tag` span with the name, attributes and values nested inside it: the
brackets and the `=` before each value take the punctuation colour, and the element name
takes the storage colour. Attribute names take the variable colour, which keeps them apart
from the element name, and their values take the string colour. The punctuation role is
read by `hljs-tag` alone, so it covers a tag's brackets and `=` signs; highlight.js's
`hljs-punctuation` class stays in the plain code colour.

## More languages

The same rules colour every language highlight.js supports. Every sample on this page is
highlight.js 11 output, so what renders here is what a project running the highlighter
gets.

### JavaScript

`KEY` is marked as a constant and takes the constant colour, and the regular expression
takes the regexp colour. `this`, `null`, `localStorage` and `console` take the storage
colour with the keywords. Inside the template literal the interpolation drops back to the
plain code colour, apart from the `this` in it.

<Canvas of={SyntaxStories.JavaScript} />

### CSS

Every selector takes the escape colour, `:root` and pseudo-elements included, while the
quoted value inside the attribute selector is a string. The custom property being
declared matches the property names, `!important` takes the storage colour, and bare
keywords such as `all`, `ease` and `none` stay in the plain code colour.

<Canvas of={SyntaxStories.Css} />

### JSON

Keys take the variable colour and values the string colour. `false` and `null` take the
storage colour like any other literal. Braces, brackets, colons and commas are
`hljs-punctuation` and stay plain.

<Canvas of={SyntaxStories.Json} />

### YAML

Keys take the variable colour, colon included, and unquoted values are strings. The list
dashes take the storage colour, `10` the number colour and `true` the storage colour.

<Canvas of={SyntaxStories.Yaml} />

### Shell

The shebang is `hljs-meta` and takes the storage colour, the same as `if`, `then` and
`fi`. Commands on highlight.js's built-in list take the type colour: shell built-ins such
as `set` and `echo`, and core utilities such as `rm`. `node` and `pnpm` are not on it and
stay plain. The variable inside the string takes the variable colour.

<Canvas of={SyntaxStories.Shell} />

### Dockerfile

Instructions take the storage colour and port or version numbers the number colour.
highlight.js reads what follows `RUN`, `COPY` and `WORKDIR` as shell, so a shell built-in
such as `enable` picks up the type colour there.

<Canvas of={SyntaxStories.Dockerfile} />

### Markdown

Headings take the storage colour in bold, and list bullets the same colour at normal
weight. Inline code and fenced blocks take the string colour, as do link text and URLs,
and a quote takes the comment colour. Bold and italic text keep the plain code colour and
change only weight or style; emphasis is the only thing this theme sets in italics.

<Canvas of={SyntaxStories.Markdown} />

### Diff

Removed lines take the string colour and added lines the number colour. The file header
is `hljs-comment`, the hunk range is `hljs-meta` in the storage colour, and context lines
stay plain.

<Canvas of={SyntaxStories.Diff} />

## Retinting

Assign a role on the block, or on an ancestor inside the same theme, and every rule that
reads it follows. Here it is inline on the `pre`, so it holds in both themes. Use one of
the selectors in the note below for a project-wide change, or set it on one element for a
single figure.

<Canvas of={SyntaxStories.Retint} />

> Each theme declares its own code colours: dark blocks sit on deep navy, light ones on
> white with navy text. The brand declares both at the specificity of `:root`, so a rule of
> the same weight placed after the brand wins. `:root, [data-theme]` changes a role in both
> themes, and `[data-theme="light"]` in light mode only. For dark mode only, use
> `:root:not([data-theme="light"]), [data-theme="dark"]`, which also covers a page that
> sets no attribute.

## On its own

The syntax theme is part of the main bundle, so a project that already loads
`@kostad/brand` has it. It is also an entry of its own,
`@use "@kostad/brand/scss/entries/syntax"`, for a project that wants the theme and none
of the rest. That entry emits the `hljs` rules only, so pair it with
`@kostad/brand/scss/entries/tokens` unless the page already declares the custom
properties.
